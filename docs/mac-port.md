# GridCraft for Mac: SwiftUI frontend

Last updated: 2026-10-17

A native macOS frontend in SwiftUI over GridCraft's Rust engine, in a fork of `storytold/gridcraft`. The egui frontend stays in the tree as the behaviour reference.

## Status

**MAC1 done** (engine read models); **MAC6 done** for the common dialogs (forms, Find/Replace, Go To, Sort, Name Manager, Insert Function, Goal Seek, rules, results, pictures); the rest is listed below. Next task: **MAC7** (objects and output).

- **MAC1.1 done.** `gridcraft_engine::viewport` lays out a block of cells: `viewport(wb, &ViewportRequest, &mut CfCache, &dyn Measure) -> Viewport`, giving `CellView`s (span/merge, fill, data bar, icon, checkbox, picture, `CellText`, border segments, comment mark) plus sparklines and filter buttons. egui's `grid::paint_quadrant` now only places and draws what the model returns (pixel-identical to before on the sample workbooks and a stress sheet at 50/100/175%, frozen panes, Page Layout, right-to-left and Show Formulas). `print.rs` shares its `cell_look`. `display::formula_display` (Show Formulas in the UI's formula language) moved from `ui-egui` into the engine.
- **MAC1.2 done.** `gridcraft_engine::selection_format::selection_format(wb, sheet, &Selection) -> SelectionFormat`, also the query command `selection.format` (JSON, `null` = mixed): the active cell's style (what toggles flip; `active_style` is shared by the engine's toggle commands and egui's ribbon), the cell count, and the selection's font, fill, alignment, number format (code + category), borders (outline, inside horizontal/vertical, diagonals; an edge counts when set on either neighbouring cell) and protection. It reports the cells' own formatting (what Format Cells edits), not table styles or conditional formats. Selections over 250,000 cells (or edges over 65,536 cells) are summarized from their distinct styles, so a whole-sheet selection stays instant.
- **MAC1.3 done.** Moved out of egui's `SheetApp` into the engine: `edit.commit` (an entry in the interface's formula syntax, `locale: en|es`, made canonical, checked against data validation: a Stop rule rejects it with `{committed: false, validation}`, Warning/Information enter it and return the message; then `cell.set` or `range.fill`, which journal and undo it as usual: the new `cmd!(delegate …)` form), `formula_locale` (canonical / display / templates), `host_clipboard::HostClipboard` on `Session` (published/unpublished copies, cut pastes once; frontends read and write the system clipboard and ask it what to paste), `DocState::autosave_due` + `AUTOSAVE_DELAY_MS`, `view_state` (scroll offset ↔ saved `topLeftCell`), `notice::open_notice` (the info bar for `file.open` warnings) and `selection::name_box_text`.
- **MAC1.4 done.** `gridcraft_engine::geometry::Geometry` (Normal view): column/row edges and hit-testing for a scroll offset, cells-area origin and size and zoom scale; frozen panes (`panes()`, `range_panes()`), `scroll_rows/cols`, `reveal(cell)` (the scroll that brings a cell into view), `col_edge`/`row_edge` (resizing), `anchor_rect`/`object_at` (floating objects), `fill_handle`, `filter_button`, and `hit()` → object / fill handle / selection border / filter button / cell. egui's `Geo` uses it in Normal view (pixel-identical, also scrolled with frozen panes at 60/100/150%); Page Layout view keeps `paper::PageGrid`.
- **MAC2.1 done.** `crates/ffi` (`gridcraft-ffi`, L6, UniFFI 0.32): `Engine` (one `Session`) with `execute(id, params JSON) → JSON`, `take_ui_requests()`, `commands()`, `revision()`, typed `viewport(query, TextMeasurer)`, `selection_format()`, `geometry(origin, size, scroll, scale) → GridGeometry` (positions, panes, `reveal`, edges, `hit`), plus `saved_scroll`/`store_scroll`, `name_box_text`, `autosave_due`, `open_notice` and the clipboard rules (`clipboard_published/unpublished`, `paste_for_text/command`). `TextMeasurer` is a Swift callback interface (Core Text), cached per request on the Rust side; non-finite widths become 0. Every call runs under `catch_unwind` (`FfiError::Internal`). The crate allows `unsafe` only for UniFFI's scaffolding: `#![deny(unsafe_code)]` covers the handwritten code. Swift-facing names avoid Swift/Foundation ones (`CellRange`, `GridRect`, `GridPoint`…). Bindings: `cargo run -p gridcraft-ffi --features bindgen --bin uniffi-bindgen -- generate --library <lib> --language swift`. Generated Swift is exempt from the no-force-unwrap rule, like generated Rust.
- **MAC2.2 done.** `macos/build-engine.sh` builds `gridcraft-ffi` for arm64 + x86_64 (rustup's toolchain, `MACOSX_DEPLOYMENT_TARGET=26.0`), `lipo`s them, generates the Swift bindings and packs `macos/GridCraftEngine/GridCraftFFI.xcframework`. The Swift package `macos/GridCraftEngine` (Swift 6 mode) wraps it with `CoreTextMeasurer` (Core Text widths, unknown fonts fall back to the system font; font substitution for Office fonts is still to do). `swift test` drives the engine from Swift. Build outputs are gitignored. See `macos/README.md`.
- **MAC3.1 done.** `macos/GridCraft` (SwiftPM): `GridCraftUI` library (`SpreadsheetDocument`, a `ReferenceFileDocument` over one engine session: opens xlsx/csv/tsv through `file.open {name, base64}`, saves through `file.saveBytes`), the `GridCraft` `DocumentGroup` app (File ▸ New from Sample), and `macos/build-app.sh`, which wraps the binary into `target/mac/GridCraft.app` with an Info.plist declaring the document types (ad-hoc signed). FFI additions: `selection()`, `sheet()`, `column_label`, `cell_name`, `range_name`, `CfIcon.count`, `BorderSegment.width`.
- **MAC3.2 done.** `GridNSView` (layer-backed, scrolls itself: trackpad/wheel, ⌘-scroll and pinch zoom, click and Shift-click select, arrows/Tab/Enter move and reveal) drawn by `GridRenderer`: headers, gridlines, per-pane cells from the engine's viewport (fills, Core Text text with spill/wrap/rotation, data bars, icons, checkboxes, borders, comment marks, sparklines, filter buttons), frozen panes and the selection. `grid-snapshot` renders offscreen. **Frame time** (M5 Pro, release, 1400×900 pt at 2×, full redraw, no caching): a 100,000-row sheet scrolled to row 40,000 (≈550 text cells) draws in a median 11.5 ms (the first frame ~35 ms, building Core Text fonts); the sales sample in 1–4 ms. 60 fps holds; 120 fps needs tile caching (redraw only what scrolled in) — MAC4 or later.
- Crash fixed during MAC3: changing SwiftUI state from `draw(_:)` (the frame-time label) made AppKit throw at launch. Reports now go out after the display pass; regression test `drawingReportsTheFrameTimeOnlyAfterTheDisplayPass`.
- Follow-ups from MAC3: **font substitution** (files use Calibri, which macOS lacks; the system font is wider, so the sales sample's total shows `####` where egui, with metric-compatible Carlito, fits it); dark mode for the chrome; tile caching; sparkline rendering through the engine's chart primitives instead of the simplified Swift drawing; pictures and floating objects (MAC7).

## Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-10-17 | Fork, not upstream | Upstream requires Rust-only, all-platform UI. A Swift frontend can't live there. |
| 2026-10-17 | Toolbar + inspector + menu bar; no ribbon, no keytips | Native Mac conventions. |
| 2026-10-17 | UniFFI bridge crate `crates/ffi` (L6); the only crate allowed generated `unsafe` | Typed Swift bindings without handwritten C ABI. The JSON control channel is too slow for the grid. |
| 2026-10-17 | Grid = custom AppKit view via `NSViewRepresentable` | SwiftUI `Table`/`LazyVGrid` can't handle 1,048,576 × 16,384 cells, frozen panes or 120 fps scrolling. |
| 2026-10-17 | Cell appearance and editing rules move into the engine as read models | Avoids two diverging copies (egui and Swift) of Excel behaviour. |
| 2026-10-17 | SF Symbols allowed through the system API only | Native look; nothing vendor-owned is committed. |
| 2026-10-17 | Swift app lives in `macos/`, not `apps/` | `apps/*` are Cargo workspace members. |
| 2026-10-17 | App built with SwiftPM + `build-app.sh` (Info.plist assembled by script), not an Xcode project, for now | Scriptable, reviewable, no generated project file. Revisit when App Intents, Quick Look and other extensions (MAC8) need an Xcode project. |
| 2026-10-17 | The viewport model measures text through a frontend-supplied `Measure` trait (text, font, size → width) | `####`, General narrowing, Shrink to fit, repeat fills and overflow depend on font metrics only the frontend has. The decisions stay in the engine; egui measures with its painter, Swift will with Core Text (a UniFFI callback interface). Lengths are in screen units (`scale` per sheet unit), relative to the cell; overflow is given as columns, so the frontend maps it with its own geometry. |

## Phases

### MAC1: engine read models (Rust; egui switches to them too)
- **MAC1.1** Viewport read model: for a sheet and a row/column window, every visible cell's final text, font, colours, alignment, borders, overflow extent, merge, and conditional-format decorations (data bars, icons). Today this lives in `crates/ui-egui/src/grid.rs` (`look`, `display_text`, `merged_edges`, `center_across_end`, `shrink_font`); move it into `crates/engine`, and make `grid.rs` consume it.
- **MAC1.2** `selection.format` query: the selection's resolved font, fill, alignment, number format and borders, with a "mixed" state when cells differ. This is what the inspector and toolbar show.
- **MAC1.3** Move the business logic in `crates/ui-egui/src/lib.rs` (`SheetApp`) into the engine: validation on commit, cut-pastes-once clipboard semantics, AutoSave policy, `store_view_state`, the open-warning notice, and the Name Box text.
- **MAC1.4** Geometry queries for the grid: row/column positions and sizes, hidden/frozen ranges, and hit-testing (point → cell, header edge, fill handle, object).

### MAC2: bridge
- **MAC2.1** `crates/ffi` with UniFFI: `Session` handle, `execute(id, json) -> json`, `take_ui_requests()`, `commands()`, and the read models from MAC1. Panics are caught at the boundary.
- **MAC2.2** Build an XCFramework (arm64 + x86_64) and Swift Package `macos/GridCraftEngine`; script it (`cargo xtask mac-framework` or a shell script).

### MAC3: spike: read-only document
- **MAC3.1** `DocumentGroup` app opening `.xlsx`/`.csv` through the engine, with a sample workbook from `crates/engine/src/sample.rs`.
- **MAC3.2** Grid `NSView`: headers, gridlines, cell text through Core Text, scrolling, zoom, frozen panes. Measure frame time on a 100k-row sheet.

### MAC4: editing
- **MAC4.1** Selection (drag, Shift/⌘-click, row/column headers, the corner), keyboard navigation, undo/redo through the engine's history and the window's `UndoManager`, the system clipboard (plain text + HTML, cut pastes once).
- **MAC4.2** In-cell editor (`NSTextView`, IME, formula point mode, function autocomplete and argument hints, column AutoComplete, localized formulas), the formula bar and the Name Box. The editing rules in `crates/ui-egui/src/editor.rs` move into the engine first.
- **MAC4.3** Fill handle, resizing rows and columns.

### MAC5: toolbar, inspector, menus
- **MAC5.1** The menu bar from the engine catalog and the Mac placement table, the command palette (⇧⌘P), handling the commands' UI requests.
- **MAC5.2** The customizable toolbar.
- **MAC5.3** The inspector (Cell and Sheet panes first).
- **MAC5.4** Context menus.

### MAC6: dialogs
- **MAC6.1** The form dialogs' specs move into the engine (`forms`), egui draws them from there.
- **MAC6.2** One SwiftUI sheet draws every engine form.
- **MAC6.3** The dialogs that aren't forms: Find and Replace, Go To, Sort, Name Manager, Insert Function, Conditional Formatting Rules Manager, Goal Seek, Solver, Analysis ToolPak, Recommended Charts, Select Data, the result viewers (statistics, accessibility, error checking, evaluate formula, spelling, macros, journal), About, Insert Picture.

### MAC7: objects and output
Charts (paint `gridcraft-chart` `Prim`s with Core Graphics), pictures, shapes, text boxes, sparklines, Page Layout view, printing (`NSPrintOperation` over the engine's PDF), export.

### MAC8: platform
App Intents for engine commands (Shortcuts, Siri, Apple Intelligence), the control channel for agents, String Catalogs (generated from `crates/ui-egui/src/i18n/*`), Quick Look preview, Spotlight, and sharing.

## Toolbar + inspector design

Placement of the Excel ribbon groups (engine catalog `menu` paths) in the Mac UI.

**Toolbar** (customizable, `.toolbar(id:)`): Undo/Redo, Format Painter · Font, Size, Bold/Italic/Underline, Font Colour, Fill · Alignment (segmented), Merge, Borders menu · Number Format menu (Currency, Percent, Comma, ± decimals) · AutoSum, Sort & Filter · Insert menu (Chart, Table, PivotTable, Picture, Shape, Link, Comment) · Zoom · Inspector toggle.

**Inspector** (`.inspector`, panes follow the selection):

| Pane | Replaces | Shown |
|---|---|---|
| Cell: Font, Alignment, Number, Border, Fill, Protection | Home ▸ Font / Alignment / Number; Format Cells dialog | Always |
| Table | Table Design ▸ Style Options / Styles / Properties | Selection in a table |
| Chart | Chart Design ▸ Type / Layouts / Data; Format ▸ Shape Styles | Chart selected |
| PivotTable | Field list (`pivot_pane.rs`); PivotTable Analyze / Design | Selection in a pivot |
| Sheet | Page Layout ▸ Page Setup / Sheet Options / Themes; View ▸ Show | Always |
| Data | Data Validation, Conditional Formatting rules, Outline | Always |

Comments and notes get their own sidebar.

**Menu bar**: File, Edit, View, Insert, Format, Formulas, Data, Review, Window, Help. Built from the engine catalog (`menu[0]` → menu, `menu[1]` → section), re-mapped by the Swift placement table where Mac conventions differ (e.g. Page Setup under File). Everything else lives here: Formulas ▸ Auditing, Review ▸ Proofing / Protect, Data Tools, View ▸ Window, Automate. A command palette (⌘⇧P, the engine's `commandSearch`) reaches every command.
